# API summary

Generated by `scripts/make_api_summary.py` from the code. Do not edit by hand; re-run the script when a public name changes. Modules are listed in layer order: a module only uses the ones above it. Names starting with `_` are private and left out.

## models.py

The project's vocabulary: simple containers for the data every other file works with.

- `BREAK = 'BREAK'`
- `Severity` (choices: ERROR, WARNING) - How serious an Issue is.
- `Issue(severity: Severity, message: str, row: int | None)` - One problem or warning found while reading or checking input.
- `InputError` (exception) - Raised when input is unusable.
- `PerformerData(performances_by_performer: Mapping[str, frozenset[str]], performer_names: Mapping[str, str], performance_names: Mapping[str, str])` - The cleaned contents of the performer CSV. Also: performance_keys, performers_by_performance.
- `PerformerLoad(data: PerformerData, warnings: tuple[Issue, ...], rows_read: int, rows_used: int)` - What the performer loader returns: the cleaned data plus how loading went.
- `ConflictMap(shared: Mapping[frozenset[str], frozenset[str]], neighbours: Mapping[str, frozenset[str]])` - Which performances clash, and which performers cause each clash. Also: conflict(), shared_performers().
- `Schedule(name: str, slots: tuple[str, ...], display_names: Mapping[str, str])` - One running order: slot 1 is the first item, and so on. Also: num_slots, num_breaks, positions().
- `ScheduleLoad(schedules: tuple[Schedule, ...], warnings: tuple[Issue, ...])` - What the schedule reader returns: every schedule in the file, plus any warnings.
- `Pins(slots: Mapping[int, str], display_names: Mapping[str, str])` - Items the organiser has fixed to chosen slots (the schedule finder's fixed positions). Also: break_positions, performance_positions.
- `PinLoad(pins: Pins, warnings: tuple[Issue, ...])` - What the fixed-positions reader returns: the pins plus any warnings.
- `Violation(performer: str, performance_a: str, position_a: int, performance_b: str, position_b: int, slots_between: int, required: int)` - One broken spacing rule: a performer who has too little rest between two performances.
- `ScheduleCheck(schedule_name: str, gap_required: int, num_slots: int, num_breaks: int, problems: tuple[Issue, ...], violations: tuple[Violation, ...], smallest_gap: int | None)` - The result of checking one schedule. Also: valid.
- `FinderStatus` (choices: FOUND, EXHAUSTED, STOPPED) - How a run of the schedule finder ended.
- `FinderResult(status: FinderStatus, schedules: tuple[Schedule, ...], explanation: tuple[Issue, ...], blocking_pins: tuple[int, ...])` - What the schedule finder returns.

## io.py

Reading and cleaning input files.

- `ID_SIMILARITY = 0.9`
- `PERFORMANCE_SIMILARITY = 0.92`
- `clean_text(text: str) -> str` - Tidy text for display: standard Unicode form, no stray or repeated spaces.
- `make_key(text: str) -> str` - The cleaned, lower-case form used for all matching (see models.py).
- `read_text(path: str | Path) -> str` - Read a text file as UTF-8 (a byte-order mark added by Excel is accepted).
- `parse_performers(text: str, id_column: str | None = None, performance_column: str | None = None) -> PerformerLoad` - Clean performer CSV text into a PerformerLoad.
- `load_performers(path: str | Path, id_column: str | None = None, performance_column: str | None = None) -> PerformerLoad` - Read a performer CSV file and clean it.
- `parse_schedules(text: str) -> ScheduleLoad` - Read schedule CSV text: a `position` column and one column per schedule.
- `load_schedules(path: str | Path) -> ScheduleLoad` - Read a schedule file (one or several schedules side by side).
- `parse_pins(text: str) -> PinLoad` - Read fixed-positions CSV text: a `position` column and an `item` column.
- `load_pins(path: str | Path) -> PinLoad` - Read a fixed-positions file.
- `format_schedules(schedules: Sequence[Schedule], performance_names: Mapping[str, str]) -> str` - CSV text for one or several schedules side by side (the format of docs/input-data.md).
- `schedules_file_name(seed: int | None, pick: str) -> str` - The name of a schedules file (decision D43): the seed, if any, and the pick.
- `check_output_free(path: str | Path) -> None` - Raise InputError if the file already exists.
- `write_schedules(path: str | Path, schedules: Sequence[Schedule], performance_names: Mapping[str, str]) -> None` - Write schedules side by side to a CSV file (decision D43).
- `write_text(path: str | Path, text: str, *, exclusive: bool = False) -> None` - Write a text file.

## conflicts.py

Works out which performances clash, and which performers cause each clash.

- `build_conflict_map(data: PerformerData) -> ConflictMap` - Build the conflict map for a show.

## selection.py

Reading a typed choice of numbers such as "1,4,9", "1-3, 7" or "all".

- `Selection(ranges: tuple[tuple[int, int], ...], select_all: bool)` - A set of chosen numbers, or "everything". Also: count, highest, numbers().
- `parse_selection(text: str, *, maximum: int | None = None, max_count: int | None = None) -> Selection` - Read a typed choice.
- `selection_from_numbers(numbers: Iterable[int]) -> Selection` - A Selection of exactly these numbers, written as joined ranges (empty if none).
- `schedules_to_request(selection: Selection, limit: int) -> int` - How many schedules to ask the finder for: up to the highest one chosen, plus one more.
- `Picked(schedules: tuple[Schedule, ...], numbers: Selection, missing: Selection, more_exist: bool | None, total: int | None)` - What a choice picks out of the finder's list (see apply_selection).
- `apply_selection(result: FinderResult, selection: Selection, limit: int) -> Picked` - Pick the chosen schedules out of a finder result (decisions D17, D19, D33).

## report.py

Turning check results into words for the organiser.

- `MAX_ISSUES_SHOWN = 20`
- `PairProblem(performance_a: str, position_a: int, performance_b: str, position_b: int, slots_between: int, required: int, performers: tuple[str, ...])` - One pair of performances that are too close together, and who is affected.
- `group_violations(violations: Sequence[Violation]) -> tuple[PairProblem, ...]` - Gather violations by pair of performances, in running order.
- `describe_pair(pair: PairProblem, data: PerformerData) -> str` - One sentence about one pair of performances that are too close together.
- `format_issues(heading: str, issues: Sequence[Issue], limit: int = 20) -> str` - A heading followed by one indented line per issue (shortened if there are many).
- `format_check(check: ScheduleCheck, data: PerformerData) -> str` - The full write-up for one schedule.
- `format_overview(checks: Sequence[ScheduleCheck]) -> str` - A table with one row per schedule, so several can be compared at a glance.
- `format_totals(checks: Sequence[ScheduleCheck]) -> str` - One closing sentence for a run that checked several schedules.
- `format_violations_csv(checks: Sequence[ScheduleCheck], data: PerformerData) -> str` - CSV text with one row per violation, using the names from the performer file.
- `format_written(count: int, numbers: str, path: str) -> str` - One sentence saying what was written and where.
- `format_availability(more_exist: bool | None, *, total: int | None, produced: int, last_number: int) -> str` - Whether the finder's list goes on: more exist, this is all of it, or the search was stopped.
- `format_missing(numbers: str, count: int, *, stopped: bool, total: int | None) -> str` - Schedule numbers that were asked for but are not in the list.
- `format_larger_gap_prompt(gap: int) -> str` - A plain invitation to try a longer rest next time (decisions D14, D16).
- `format_no_schedules(status: FinderStatus, explanation: Sequence[Issue]) -> str` - The heading and the reasons when the finder produced no schedule at all.

## validator.py

The schedule checker's logic: is this running order valid, and if not, why not?

- `SUGGESTION_SIMILARITY = 0.85`
- `check_schedule(data: PerformerData, schedule: Schedule, gap: int = 1) -> ScheduleCheck` - Check one schedule.
- `check_schedules(data: PerformerData, schedules: Sequence[Schedule], gap: int = 1) -> tuple[ScheduleCheck, ...]` - Check several schedules (such as the columns of a side-by-side file), in order.

## solver.py

The schedule finder's logic: find valid running orders, or explain why there are none.

- `DEFAULT_TIME_LIMIT = 30.0`
- `SolverNotInstalled` (exception) - OR-Tools is missing.
- `slots_needed(performances: int, gap: int) -> int` - The fewest slots that `performances` mutually clashing performances can fit in.
- `solver_version() -> str` - The OR-Tools version in use.
- `find_schedules(data: PerformerData, *, gap: int = 1, breaks: int = 0, pins: Pins | None = None, seed: int | None = None, count: int = 1, time_limit: float = 30.0) -> FinderResult` - List the first `count` valid schedules, or say why there are none.
